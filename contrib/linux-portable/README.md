# Linux x86_64 portable test builds

The Dockerfile prepares Ubuntu 20.04 x86_64 with wallet-compatible Berkeley DB 4.8, OpenLibm 0.8.7 and Qt 5.12. `build.sh` builds a clean Git archive mounted at `/source` and writes an AppImage plus standalone daemon/CLI/transaction binaries to `/output`. These are test artifacts, not official releases. `package.sh` can also package a previously built source/build directory. Existing consensus and wallet code are not changed.

The workflow builds from the exact checked-out commit, verifies download hashes and the output SHA256 manifest, then tests Ubuntu 22.04 and 24.04 containers without old Boost installed. Tests audit ELF dependencies and copy only the headless binaries to an empty directory with `LD_LIBRARY_PATH` unset, then cover isolated regtest RPC/wallet/mining and Qt startup under Xvfb; the AppImage is extracted because CI does not provide FUSE. Normal FUSE mounting, hardware desktops, public-network masternodes and real wallet transactions require separate validation. Containers install normal desktop prerequisites (libGL, fontconfig/fonts, Xvfb and xauth). Offscreen Qt full startup is not a substitute: its system-tray path has crashed in testing.

The linuxdeploy, Qt plugin, appimagetool and runtime downloads use SHA-256 values pinned in `package.sh`. Their upstream `continuous` URLs can change, causing a deliberate verification failure. Only update the pins after obtaining and verifying the new official release metadata and repeating compatibility tests. Berkeley DB and OpenLibm sources are likewise checksum verified. Static or bundled legacy dependencies must be reviewed and updated deliberately; this workflow does not establish a security or release approval.
