# PEPEPOW Core v2.9.0.6 — Build Provenance and Packaging

This technical reference records the source and output requirements for the optional v2.9.0.6 release.

## Source and build status

- Official integrated candidate: `MattF42/PePe-core:master` at `1522845bcd6c75ab5086f96d2a9977eecef74849` after PR #41.
- [Linux x86_64 build](https://github.com/MattF42/PePe-core/actions/runs/43278927487), [native ARM64 build](https://github.com/MattF42/PePe-core/actions/runs/43279015136), and [Windows x86_64 build](https://github.com/MattF42/PePe-core/actions/runs/43279092716) passed from that source.
- These are `-test-` artifacts with `_CLIENT_VERSION_IS_RELEASE=false`; they are **not** official release binaries.

## Release package contents

Expected platform archives:
- `PEPEPOW-v2.9.0.6-<shortSHA>-release-x86_64-w64-mingw32.zip`
- `PEPEPOW-v2.9.0.6-<shortSHA>-release-x86_64-linux-gnu.tgz`
- `PEPEPOW-v2.9.0.6-<shortSHA>-release-aarch64-linux-gnu.tgz`

The Windows archive contains Qt, daemon, CLI and tx executables (with `.exe`). Each Linux archive contains `PEPEPOW_qt`, `PEPEPOWd`, `PEPEPOW-cli` and `PEPEPOW-tx`. Archives must exclude wallet data, seeds, keys and debug logs.

## Final build sequence

1. Review the final source diff for optional/no-consensus-change classification and approve the release note content.
2. Commit the release flag change, preserving `2.9.0.6`, then freeze the final **official SHA**.
3. Rebuild **all three** platforms from that exact SHA; do not relabel earlier candidate binaries.
4. Verify startup/version strings, architecture, native Linux compatibility, package contents and SHA256 manifests. Verify the final Windows Qt package on Windows as appropriate.
5. Publish only after final checks, with exact-SHA build provenance and a matching `v2.9.0.6` tag.

## Known upgrade behavior

A previously cached Masternode list may show stale local statuses. After stopping the application, backing up and refreshing `mncache.dat` and `netfulfilled.dat` corrected one observed Windows status discrepancy. An older wallet file can trigger a one-time transaction rescan.

For implementation risk detail, see [the technical validation record](../pepepow-v2.9.0.6-second-pass-audit-and-branch-cleanup.md).
